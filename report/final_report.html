Compact Raw-IMU Activity Recognition on UCI HAR

Take-home exercise, research assistantship, Embedded Systems Laboratory (ESL), EPFL.

Task. Train a neural network with fewer than 20,000 trainable parameters that classifies human activity from a window of raw accelerometer and gyroscope signals (no handcrafted features). Assess it with accuracy, F1 and a confusion matrix, and discuss strengths, limitations and failure cases.

What was built. Three hand-designed 1D CNNs (Models A, B, C) were compared on a subject-held-out validation split. Model C was selected and retrained on all official training subjects for a fixed 17 epochs. Afterwards a fourth, strictly causal network (Model D) and a linear baseline were trained as a validation-only extension, to place all models on an accuracy-vs-cost Pareto plot.

Headline result (official test set, 9 unseen subjects, 2,947 windows, Model C, 17 epochs, 8,862 parameters): accuracy 0.9240, macro-F1 0.9231.

1. Data and preprocessing

UCI HAR: 30 subjects, six activities (WALKING, WALKING_UPSTAIRS, WALKING_DOWNSTAIRS, SITTING, STANDING, LAYING), smartphone on the waist, 50 Hz, pre-segmented into 128-sample windows (2.56 s, 50 % overlap). The official split is subject-independent: 21 training subjects (7,352 windows) and 9 test subjects (2,947 windows).

  • Raw signals only. Input is (6, 128) per window: total_acc_x/y/z and body_gyro_x/y/z. The precomputed 561-feature files (X_train.txt, X_test.txt) are never opened; the loader refuses to read them and this is covered by a unit test.
  • total_acc rather than body_acc. Gravity direction is the main cue separating the static postures. The sensor ablation in Section 6 supports this choice.
  • Validation = held-out subjects, not windows. Windows overlap by 50 %, so a window-level split would put near-duplicates on both sides. Four of the 21 training subjects (1, 3, 25, 27) are held out for model selection; the other 17 train.
  • Normalisation. Per-channel z-score, statistics computed on training data only. For the final model they are recomputed on all 21 training subjects and stored in the checkpoint; the test set is only ever transformed with them.
  • Test-set discipline. The test split is never loaded by training or by any selection step.

2. Models

All networks follow Conv1D -> BatchNorm -> ReLU -> (pool) -> ... -> Global Average Pooling -> Linear. The architectures are declared once in src/architectures.py, and parameter and MAC counts are computed from that single specification (and cross-checked against hooks on the real PyTorch module).

2.1 Models A, B, C (the primary comparison)

Model Idea Params MAC / window Local receptive field
A Minimal: 2 conv layers (6->16 k9, 16->32 k5), 1 pooling 3,766 274,624 18 samples (0.36 s)
B 3 dense conv layers (16/32/64 ch), 2 pooling stages 14,390 602,496 36 samples (0.72 s)
C Depthwise-separable blocks (k9 depthwise + 1x1 pointwise), 24/48/96 ch, 2 pooling stages 8,862 415,296 60 samples (1.20 s)
  • A is the "how little is enough?" floor.
  • B adds depth with full convolutions: more capacity, larger receptive field, but the most parameters and compute.
  • C swaps dense convolutions for depthwise-separable ones. It reaches a receptive field 67 % larger than B's with 38 % fewer parameters and 31 % fewer MACs, because it never forms a large C_in x C_out x K kernel.

2.2 Model D (the causal extension, trained after A/B/C were frozen)

A, B and C use symmetric ("same") padding, so each output depends on future samples and cannot run sample-by-sample on a stream. D was designed to remove that obstacle:

  • four stages of dilated, depthwise-separable, left-padded (causal) convolutions, kernel 5, dilations 1/2/4/8, channels 6->16->24->32->48;
  • no pooling, so every layer has a fixed-size history buffer;
  • 3,906 parameters, 406,560 MACs/window, receptive field 61 samples, then GAP + Linear.

D was specified once from first principles before any validation number existed and was not tuned afterwards. A Linear baseline (Linear(768, 6) on the flattened window, 4,614 parameters) tests whether nonlinear temporal modelling is needed at all.

All five models are far below the 20,000-parameter limit.

3. Training protocol

Phase 1 - architecture comparison (validation only). A, B, C x 3 seeds (0, 1, 2) on the fixed 17/4-subject split with identical settings: Adam (lr 1e-3, weight decay 1e-4), batch 64, cross-entropy, up to 100 epochs, early stopping (patience 15) and ReduceLROnPlateau on validation macro-F1, best-validation-F1 checkpoint. The only things that vary are architecture and seed. The winner is the highest mean validation macro-F1, a rule fixed beforehand.

Phase 2 - final model. The selected architecture is retrained from scratch (seed 123) on all 7,352 training windows with no validation set, for a fixed budget round(mean(epochs_ran)) = round(mean([17, 17, 18])) = 17 epochs, and the last-epoch weights are saved. The budget comes only from Phase-1 training durations.

Single test evaluation. The 17-epoch checkpoint was then evaluated once on the official test set (Section 5); the evaluation script refuses to overwrite an existing result.

Provenance note. An earlier draft of Phase 2 used the epoch of best validation F1 (1 epoch) and was evaluated on the test set before the budget rule was changed to the training-duration rule. That checkpoint is not the submitted model and none of its numbers appear below; it is archived under results/historical_original_protocol/ only for transparency. Because that earlier evaluation had been seen, the test number here should be read as a one-shot result of a rule that was fixed from Phase-1 behaviour, not as a blind first look.

Pareto frontier: accuracy against cost

A model is dominated if another model is at least as accurate and at most as costly, with at least one strict inequality.

def dominated(metric, cost):
    out = {}
    for a in names:
        by = [b for b in names if b != a and metric[b] >= metric[a] and cost[b] <= cost[a]
              and (metric[b] > metric[a] or cost[b] < cost[a])]
        out[a] = by
    return out

Reading the Pareto plot (validation only, 4 subjects, 3 seeds, so these are indications rather than significance claims):

  • A and C are on the front. A is the cheapest accurate model; C buys +0.0008 macro-F1 (inside seed noise) for 2.4x the parameters and 1.5x the MACs.
  • B is dominated by A (and by C): it costs more and scores lower, so its extra capacity was not usable at this data scale.
  • D is dominated by A. This is the price of causality and of no pooling (no MAC savings from downsampling). D is useful as a streaming-friendly design point, not as the accuracy winner.
  • Linear is non-dominated only in the MAC view, because it is nearly free (4,608 MACs); at 0.62 macro-F1 it is not a usable classifier, which confirms that nonlinear temporal feature extraction is required.
  • In the parameter view, C and A are the only non-dominated models.

Why C was still the one submitted. The selection rule (highest mean validation macro-F1) was fixed before the runs. A is the natural choice if cost matters more than a 0.0008 difference, and is flagged as the embedded candidate in Section 7.

Strengths

  • Accurate with a tiny budget. 92.4 % accuracy and 0.923 macro-F1 on unseen subjects with 8,862 parameters (44 % of the allowed budget), using raw signals only, with no feature engineering.
  • Coarse activity regime is rarely wrong. Only 9 of 224 errors (4.0 %) cross between static and dynamic activities, so "is the person moving?" is much more reliable than the 6-way label (a property of this 6-class model; no dedicated binary detector was trained).
  • LAYING is near-perfect (precision 0.994, recall 1.00): the gravity direction in total_acc is unambiguous.
  • Dynamic classes have high recall (WALKING 0.95, UPSTAIRS 0.97, DOWNSTAIRS 0.91) and the model is cheap (0.42 MMAC/window).

Failure cases

  1. SITTING vs STANDING is the dominant failure (73 + 62 = 135 of 224 errors). Both are near-static with similar waist-phone orientation; the only cue is a small tilt difference that varies between people. It is concentrated in a few subjects (see the per-subject table): subject 10 reaches only about 69 % accuracy (48 of the 135 sitting/standing errors are his or hers alone) and subjects 9 and 2 are also below 90 %, while subjects 12, 20 and 24 are at or near 99-100 %. The three worst subjects account for 173 of the 224 errors.
  2. Walking variants (77 errors): DOWNSTAIRS is confused with UPSTAIRS (27) and WALKING with DOWNSTAIRS (26). The model sees gait rhythm well but stair direction less reliably; a 2.56 s window may contain too few distinctive impact events.
  3. Subject-dependence. Per-subject accuracy ranges from about 0.69 to 1.00, so the aggregate number hides large between-person differences.

Limitations of the study

  • Validation-to-test gap. Validation macro-F1 was 0.990 (4 subjects) versus 0.923 on test (9 subjects). Four validation subjects are a small and optimistic sample of between-subject variability; the per-subject spread above is consistent with this, but I did not run an experiment that isolates the cause. A leave-subjects-out cross-validation would give a more honest model-selection signal.
  • Selection on one split, 3 seeds. The A-vs-C difference (0.0008) is inside seed noise; the ranking of A and C is not statistically established.
  • Model D was only evaluated on validation data, never on the test set, so no test comparison between C and D exists.
  • Windowing and non-causality. Pre-segmented overlapping windows are a dataset convenience, and A/B/C use symmetric padding, so they cannot be run sample-by-sample on a stream without redesign (D addresses this, at an accuracy cost).
  • No hardware evidence. MACs, memory and receptive fields are derived from the architecture; nothing was quantised or measured on a device.

7.3 Implications for low-power, always-on use (derived, not measured)

  • Model C at the UCI HAR hop of 64 samples (1.28 s) needs about 0.32 MMAC/s and 34.6 KB of fp32 weights (about 8.7 KB at int8, before metadata).
  • Model A needs 57 % fewer parameters and 34 % fewer MACs than C for a validation difference of 0.0008, so it is the natural candidate for a wake-up-style first stage; D is the natural starting point for a true streaming implementation because it is causal and has no pooling.
  • None of this was quantised or run on hardware.

8. Conclusions and next steps

A compact depthwise-separable CNN (Model C, 8,862 parameters) classifies raw IMU windows from unseen subjects with 92.4 % accuracy and 0.923 macro-F1. Its errors are structured: nearly all stay within the static or the dynamic group, and the dominant failure is SITTING versus STANDING, concentrated in a few subjects. The Pareto analysis shows that more capacity (B) did not help, that a causal design (D) costs some accuracy, and that A offers almost the same validation accuracy at much lower cost.

If continued: leave-subjects-out cross-validation for model selection; evaluating A and D on the test set under the same single-evaluation rule; subject-wise augmentation (orientation jitter) to attack the sitting/standing ambiguity; post-training int8 quantisation and a causal/streaming port of C or D validated against the PyTorch reference; measurements on target hardware.
